# BUG-UI-001 — 顶部导航图标显示为方块

**Severity：P2 Minor**  
**Owner 建议：Agent E / UI**  
**状态：Confirmed on physical board**

## 现象

Home 顶栏左侧 Scan 图标、右侧 Settings 图标，以及 Settings/Detail 返回图标没有正常显示图形，而是显示成多个方块 placeholder。

按钮本身的 touch hitbox 可工作：

- 左侧方块按钮可以触发 Scan；
- 右侧方块按钮可以进入 Settings。

因此当前确认是视觉/icon rendering 问题，而不是 touch/button callback failure。

## 复现步骤

1. 冷启动 v0.1.0-beta.1。
2. 观察 Home 顶栏左右两侧按钮。
3. 进入 Settings 或 Detail，观察左上返回按钮。

## Expected

- Home 左：Scan/Refresh 图标正常。
- Home 右：Settings 图标正常。
- 非 Home 页面：Back 图标正常。
- 不出现 tofu/placeholder 方块。

## Actual

所有上述 LVGL symbol 显示为方块。

## 代码线索

当前 UI 在：

`components/nearby_ui/nearby_ui.c`

`make_top_bar()` 直接使用：

```c
LV_SYMBOL_REFRESH
LV_SYMBOL_LEFT
LV_SYMBOL_SETTINGS
```

当前 production defaults：

`firmware/sdkconfig.defaults`

使用：

```text
CONFIG_LV_CONF_MINIMAL=y
CONFIG_LV_FONT_DEFAULT_MONTSERRAT_14=y
```

### 根因假设（未最终确认）

高概率是 production LVGL font/fallback 中没有包含这些 `LV_SYMBOL_*` glyph，或 minimal config 下 symbol glyph 没进入实际默认字体。

不要把“换成任意 Unicode 图标”当成默认修法，因为同样可能缺 glyph。

## Fix 要求

Agent 可自行选择低成本实现，但必须满足：

- 继续保持当前 170×320 顶栏布局；
- icon 正常显示；
- 不为了 3 个图标引入明显不必要的大字体/大 RAM 成本；
- Home/Settings/Detail 三种顶栏都覆盖；
- 保持 touch/callback 行为不变。

## Acceptance Criteria

- [ ] Home Scan 图标实机显示正常。
- [ ] Home Settings 图标实机显示正常。
- [ ] Back 图标实机显示正常。
- [ ] 三个按钮 touch 均正常。
- [ ] 不出现 placeholder 方块。
- [ ] 未引入明显异常 RAM/flash 增长；如引入新 icon font，需要报告成本。

# BUG-UI-003 — SoftAP 凭据弹窗被裁切且不可滚动

**Severity：P1 Major / Beta blocker**  
**Owner 建议：Agent E / UI，必要时与 Web Management 集成联调**  
**状态：Confirmed on physical board**

## 现象

Settings → Web Management → Start Portal 后：

- SoftAP 能正常启动；
- 外部设备 Wi-Fi 列表能看到 `NearBy-One-XXXX`；
- LVGL 弹窗能显示部分连接信息；
- 但内容区域高度不足；
- Password 被底部 `Stop Portal` 按钮遮挡/裁切；
- 弹窗不可滚动；
- 用户无法可靠读取完整密码，因此无法连接 AP。

这直接阻塞 Web Portal 和 Recognition DB QA。

## 复现步骤

1. 启动设备。
2. 进入 Settings。
3. 点击 Web Management / Start Portal。
4. 观察凭据 modal。
5. 尝试查看完整 SSID、IP、Password。
6. 尝试上下滑动 modal。

## Expected

用户无需串口即可完整获得：

```text
SSID
AP IPv4
Password
```

并能正常连接 SoftAP。

如果内容超过可见区域，必须可以垂直滚动；底部 action button 不得遮挡凭据。

## Actual

Password 无法完整读取，modal 不可滚动，`Stop Portal` 与内容发生遮挡。

## 代码线索

当前 UI：

`components/nearby_ui/nearby_ui.c`

`render_portal_modal()` 中 modal 尺寸固定为：

```c
lv_obj_set_size(g.portal_modal, 158, 202);
```

`Stop Portal` button 又被固定对齐到底部：

```c
lv_obj_set_size(stop, 116, 32);
lv_obj_align(stop, LV_ALIGN_BOTTOM_MID, 0, 0);
```

在 170×320 竖屏和当前文字排版下，实机已经证明布局不足。

## Fix 要求

不要只针对当前某一个随机密码长度硬挪几个像素。修复必须考虑实际产品约束：

- 170×320 portrait；
- SSID 为 `NearBy-One-XXXX`；
- Password 是运行时生成的 8 位十六进制字符串；
- Address 当前通常为 `192.168.4.1`；
- 字体、padding、按钮必须实际共存；
- 长文本不能被 action button 覆盖。

建议方案任选其一：

1. modal content 区做成明确可纵向滚动的容器，action button 固定在安全区域；或
2. 重新压缩 modal 信息层级，使所有必要凭据在 170×320 上一次完整显示。

## Acceptance Criteria

- [ ] Start Portal 后 SSID 完整可见。
- [ ] AP IP 完整可见。
- [ ] Password 完整可见。
- [ ] `Stop Portal` 不遮挡任何凭据。
- [ ] 若内容超高，纵向滚动可用。
- [ ] 用户只看设备屏幕即可把手机连接到 SoftAP。
- [ ] 手机连接后可以打开 `192.168.4.1` Web Portal。
- [ ] Stop Portal 后 AP 消失。
- [ ] Portal → Stop → Scan → Portal lifecycle 仍正常。

# BUG-LCD-004 — HA 蓝色实机显示为绿色，RGB565 色彩链路错误

**Severity：P1 Major / Beta blocker**  
**Owner 建议：Agent D / LCD board port；Agent E 仅配合提供 reference colors**  
**状态：Confirmed symptom; root cause not yet proven**

## 现象

NearBy UI 设计中顶部栏应为 HA 风格蓝色，但在 Waveshare ESP32-C6-Touch-LCD-1.9 实机上明显显示为亮绿色。

UI 代码的 reference color 明确是：

```c
#define NB_BLUE 0x03A9F4
```

所以这不是“UI 选错了绿色”，而是 LCD pixel/color pipeline 的实机输出与软件定义不一致。

## 复现步骤

1. 冷启动 v0.1.0-beta.1。
2. 观察 Home 或 Settings 顶栏。
3. 将实机顶部栏与代码中的 `#03A9F4` reference 比较。

## Expected

顶栏为 HA-style cyan/blue：`#03A9F4` 视觉方向。

## Actual

顶栏显示为明显绿色。

## 代码线索

### UI

`components/nearby_ui/nearby_ui.c`

```c
#define NB_BLUE 0x03A9F4
```

### LVGL port

`firmware/main/nearby_lvgl_port.c`

- production frozen to LVGL v8.3；
- `LV_COLOR_DEPTH == 16`；
- draw buffer 为 `lv_color_t[]`；
- `lvgl_flush()` 直接把 `color_map` 交给：

```c
esp_lcd_panel_draw_bitmap(..., color_map);
```

当前看不到显式的 RGB565 16-bit byte swap。

### sdkconfig

`firmware/sdkconfig.defaults`

```text
CONFIG_LV_COLOR_DEPTH_16=y
```

当前 defaults 中没有看到显式 RGB565 16-bit byte swap 配置。

### ST7789 board port

`firmware/components/nearby_board/nearby_board.c`

```c
.rgb_ele_order = LCD_RGB_ELEMENT_ORDER_RGB,
.bits_per_pixel = 16,
```

并使用 ST7789 public driver + Waveshare tuning + `INVON`。

## 根因假设（高优先级验证，不得直接当结论）

高概率是 LVGL RGB565 buffer 与 ESP LCD/ST7789 所需 pixel byte order 不一致，即 16-bit RGB565 byte swap/endian handling 缺失。

也必须排除：

- RGB/BGR order 配置错误；
- ST7789 MADCTL/board tuning 与 esp_lcd driver 的组合问题；
- invert/gamma 配置导致的其他异常。

不要只因为照片“看起来绿”就盲改 `RGB` → `BGR`。先用明确的 RGB test pattern 验证。

## Fix 要求

在真实板上建立最小 color acceptance pattern，至少显示：

```text
Red
Green
Blue
White
Black
50% Gray
NB_BLUE #03A9F4
```

确认每个 reference color 正确后，再认定修复完成。

如采用 `LV_COLOR_16_SWAP`、flush-time swap、panel transfer config 或其他方式，必须确保：

- 不引入每帧大块动态 malloc；
- 不破坏当前 DMA/flush completion；
- 不显著增加 RAM；
- 不破坏 LCD + SD shared SPI2 行为。

## Acceptance Criteria

- [ ] 红色 test patch 实机为红色。
- [ ] 绿色 test patch 实机为绿色。
- [ ] 蓝色 test patch 实机为蓝色。
- [ ] 白/黑/灰阶方向正常。
- [ ] `#03A9F4` 顶栏实机为蓝色，而不是绿色。
- [ ] Scan progress bar 颜色与 UI 定义一致。
- [ ] 不出现新的 tearing/花屏/flush hang。
- [ ] LCD + SD shared SPI2 regression 仍通过。
